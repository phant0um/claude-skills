## Comprehension Digest: claude-skills Catch-Up

This update fundamentally shifted `claude-skills` from a collection of loosely defined functions into a structured, robust system for strategic reasoning and quality control. The primary motivation is to ensure **deterministic behavior** by tightly scoping context loading and forcing multi-perspective deliberation before complex actions (like making architectural decisions or writing critical artifacts).

### TL;DR
*   **Deterministic Triggers & Scope:** Skills are now activated via explicit, non-phrase keywords (`trigger`) subject to strict scope rules (global vs. project), vastly reducing ambiguity and context load.
*   **Decision-Making Frameworks Evolved:** Introduced high-value reasoning skills (`council`, `debate`) that force structured multi-perspective reviews and arbitration, designed specifically to mitigate blind spots in strategic choices.
*   **Quality Gates Implemented:** New focus on writing quality (`content-design`/`review`), transforming the workflow from simple generation to a production pipeline featuring an explicit validation step (generate + review pattern).

## Themes

### 1. Explicit Triggers and Context Scoping
The system has been updated to replace implicit context dependency with explicit control. The introduction of `trigger` keywords (literal phrase matching) and the concept of **Scopo** (`global vs project`) ensures that a skill only runs when its context is strictly bounded. This architectural change aims to prevent skills from implicitly polluting the session context, thereby managing token load and preventing unintended behavior across different domains.

### 2. Structured Strategic Deliberation (Council & Debate)
We have introduced high-level reasoning tools designed for decision-making under uncertainty. The `council` skill forces five distinct, structured perspectives (Risk, Problem, Upside, Pragmatics, Action) to generate a comprehensive view, allowing the agent to identify blind spots centrally. Similarly, `debate` enforces formalized confrontation between two opposing stances (A vs B), complete with explicit arbitration logic, making architectural trade-offs reviewable and non-subjective.

### 3. Quality Control Pipelines (Content Design & Debugging)
The core workflow is now structured as a production pipeline rather than simple function calls.
*   **Writing Quality:** The `content-design` skill defines 5 mandatory rules (Front-load, One Idea/Sentence, Specificity) applied *before* saving. This is paired with `content-design-review`, which acts as an adversarial validator, reporting line-by-line failures (e.g., identifying introduction filler). The intent is to fix the *structure* of the artifact, not the content itself.
*   **Robust Debugging:** Skills like `diagnose` and `trace` have been formalized to enforce disciplined development loops: code fixes only after a confirmed hypothesis is registered (`diagnose`), and unexpected agent outputs are reverse-engineered (`trace`).

## Watch out for Gotchas

### ⚠️ New Behavioral Change: Dependency on Explicit Triggers
*   **Risk:** The previous implicit trigger mechanism is gone. Skills now require highly specific, literal keywords to activate. If the developer relies on ambiguous phrasing, the skill may not fire as expected, leading to unexpected silent failures.
*   **Action Item:** Ensure all future usage of skills utilizes precise keyword matching.

### ⚠️ Architectural Risk: Sequential Execution Prohibition
*   **High Risk:** The `council` and `debate` skills explicitly forbid sequential execution. Running these five-way deliberative processes sequentially will lead to contaminated perspectives, invalidating the review mechanism.
*   **Action Item:** Always execute multi-perspective skills in parallel or via a structured arbitration model (like the built-in peer review process).

### ⚠️ Configuration Shift: Scale of Concepts
*   **Change:** `CLAUDE.md` now dictates that skills must explicitly justify their scope (inline with the rules of non-leakage) and how they interact with domain concepts. Skills that become too tightly coupled to domain knowledge will be flagged for migration out of this generic package.
*   **Action Item:** Before adding a new skill, rigorously test: "Would another person in an unrelated project benefit from this?" If the answer is 'Yes,' it should live outside the vault.

### ⚠️ Review Protocol Warning
*   **Behavior Change:** The `content-design-review` currently reports failures by providing line numbers and suggested fixes (e.g., R1 FAIL: line N). It strictly reports, it **does not rewrite**. Be mindful that this is a diagnostic tool for the author, not an automatic fixer for downstream agents.
